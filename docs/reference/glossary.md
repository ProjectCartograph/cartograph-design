# Glossary

The vocabulary of the new model, by context. Inside a context a term means one thing. A workspace may set its own term for any of them in its taxonomy; these are the defaults. For the contexts, see [the domain model](../explanation/domain-model.md).

| Term | Context | Meaning | Not to be confused with |
|---|---|---|---|
| Piece of work | Work definition | The one record of something an organisation does, at any scale | A label such as project or programme, which it carries |
| Label | Work definition | What a piece of work is called (project, programme, portfolio, service, grant, product), from the profile | A kind of record with fields of its own: every label shares one record, and changing a label loses nothing |
| Intended result | Work definition | A change sought: an output (produced), an outcome (changes for people) or an impact (lasting) | A goal of the organisation, which many pieces of work may serve |
| Project | Work definition | The label for temporary work that delivers outputs toward an intended result | A programme, whose parts share one change |
| Programme | Work definition | The label for temporary work whose parts together bring about one change and its benefits | A portfolio, whose members need not share an outcome |
| Portfolio | Work definition | The label for an organisation's standing investment in other work toward its goals, with no end; its decisions fund, hold, stop or move money between its members | A programme; a list or report of many pieces of work, which holds no decisions of its own |
| Theory of change | Work definition | The steps from what is done to the change, with what must hold at each | The intended results, which say what should change but not how one step leads to the next |
| Assumption | Work definition | A condition the work takes as true and needs to hold for the change to come about, often outside the work's control, stated as the situation wanted so that it can be checked; it has an owner, how much depends on it and how well it is evidenced ([EC-PCM](bibliography.md) 3.3.3) | A risk, an uncertain event that would affect the work's objectives if it happened, with its causes and consequences and a response to it ([HMT-ORANGE](bibliography.md) Annex 5). An assumption is held to be true now or to come true; one that may not hold gives rise to a risk, and one known to fail means the work must be redesigned |
| Option | Work definition | A way forward considered before committing, with why it was kept or set aside; the options include carrying on as now and a minimum option, the least new work that would meet the need | The preferred option, the one chosen |
| If nothing new is done | Work definition | What is expected if the organisation carries on as it is, with its own costs, benefits and risks, or a plain statement that this is not known; every option is compared with it | The minimum option, which is one of the options and asks for some new work |
| Case | Work definition | The justification inside a piece of work, organised by five questions: need, value, buying or building, affordability, delivery. Its parts are the change wanted, if nothing is done, intended results, theory of change and assumptions (under need), options (value), cost (affordability) and delivery | A business case document, which presents the case to one audience and is produced from it |
| Decision | Governance | A recorded act by a role with authority (approve, approve with conditions, change the scope, try another option, pilot, defer or stop) on a version of the case | An answer from a language model, which only advises |
| Condition | Governance | Something a decision requires, with an owner and a due point | |
| Stage | Governance | A part of a piece of work's life that begins with a decision point. A profile names its stages in the workspace's taxonomy, and each maps to one stage of the reference life cycle: a stage may join several reference stages, and delivery may be split into several stages | A cycle, a repeating period that steers work without an end in place of stages |
| Decision point | Governance | The decision that opens a stage: to go on, change course, hold or stop; also called a gate. It names the role with authority to decide | A review, which advises it |
| Deciding role | Governance | The role with authority to decide at a decision point, such as a sponsor, a senior responsible owner, a board, a funder or a product owner; in a workspace of one, the person working alone | The accountable role for a result, which may differ |
| Life cycle | Governance | The stages a piece of work passes through, chosen from a recognised life cycle (such as the RIBA Plan of Work, PRINCE2's management stages, or GOV.UK's discovery, alpha, beta and live), each stage mapped to the reference life cycle; a project has at least two stages, definition and delivery | The reference life cycle, which every life cycle maps to |
| Reference life cycle | Governance | The common sequence every life cycle maps to: feasibility, appraisal, definition, delivery and operation, each stage preceded by a decision point | A life cycle, which maps to it |
| Feasibility | Governance | The reference stage that sets out the need and the case for change, and asks whether the work is worth pursuing | Appraisal, which weighs the options |
| Appraisal | Governance | The reference stage that weighs the options' costs, benefits and risks before a decision, and selects one | Evaluation, which looks back at what happened; an economic appraisal model, which Cartograph links to and does not hold |
| Definition | Governance | The reference stage that plans the selected option in full (scope, cost, commercial and delivery arrangements), ending in the decision to invest | The case, which grows through every stage |
| Delivery | Governance | The reference stage, or stages, that produce the outputs | Operation |
| Operation | Governance | The reference stage in which the outputs are used, the benefits realised and the work closed | Handover, one event within it |
| Tranche | Governance | A phase of a programme, grouping projects and related work and ending in a review; a programme is phased in tranches, not stages | A stage of a project |
| Cycle | Governance | A repeating period that work without an end is steered by (a sprint, a quarter, a season, a financial year), on which its decisions, risks and reviews fall due | A stage |
| Review | Governance | An assurance look at the work, recording how independent the reviewer was; it advises, never approves | Accepting a proposal |
| Independence | Governance | How far a reviewer stands from the work: self-review (by the author), peer review (by someone not involved in producing it) or independent review (by someone outside its management or organisation) | |
| Approved plan | Governance | The approved scope, cost, dates and benefits, kept as a named version | The current plan; a baseline |
| Handover | Governance | The acceptance of a result, its benefit tracking and its open risks by the role that carries them on | Closure |
| Closing record | Governance | What closing a piece of work records: what was delivered against what was approved, what remains and who answers for it, what was learned, how well it was governed, and the review planned after | A handover; a benefit review, which comes later |
| Indicator | Measurement | What is measured, on what scale, how, by whom, with a baseline and targets | A reading |
| Scale | Measurement | What an indicator's values can be: an amount or count, a percentage or rate, ordered levels each with a description, or categories; it sets which summaries apply | A unit, which an amount is counted in |
| Baseline | Measurement | An indicator's measured starting value, or a stated unknown with when it will be known | The approved plan |
| Reading | Measurement | A value for one period | A target |
| Target | Measurement | What is aimed for, by when; a value, a threshold or a level on the indicator's scale | |
| Aggregation | Measurement | Rolling readings up across pieces of work, periods or groups, by the indicator's aggregation rule: summed, weighted by its denominator, or not aggregable | A sum, which is one aggregation rule |
| Disaggregation | Measurement | Breaking readings down by group, such as gender, age or location | A filter, which hides the other groups |
| Benefit | Benefits and learning | The measurable improvement that follows from an outcome, seen as an advantage by those who receive it, with an owner and an expected date ([IPA-BENEFITS](bibliography.md) 3.1) | The outcome it follows from; an output |
| Disbenefit | Benefits and learning | The measurable decline that follows from an outcome, seen as negative by those who bear it; it is owned and measured like a benefit and set against the benefits ([IPA-BENEFITS](bibliography.md) 3.5) | A risk, which may or may not happen; a disbenefit is an expected consequence of the work |
| Benefit review | Benefits and learning | A judgement after delivery: realised, on track, off track or stopped | |
| Evaluation plan | Benefits and learning | How much checking is proportionate, the decisions it informs, the questions it asks, and its design, data and method of analysis, fixed with a date before outcome data are collected or analysed | Monitoring, which is the readings |
| Lesson | Benefits and learning | What was learned, findable by later work | |
| Purpose | Strategy | Why the organisation exists | |
| Goal | Strategy | A result at a level of the profile's hierarchy that work serves | |
| Gap | Strategy | A problem that threatens a goal, and who feels it | |
| Group | Strategy | People or things affected, without counts | |
| Party | Parties and money | An organisation or body with an identity | A person |
| Role | Parties and money | What a party, or a person outside the record, does in the work | |
| Funding line | Parties and money | Money from a source for a period, with currency and status | |
| Risk | Risk | The effect of uncertainty on objectives: an event that may or may not happen, stated with its causes and consequences ([HMT-ORANGE](bibliography.md) Annex 5) | An issue, which has happened; an assumption, which is held to be true |
| Risk category | Risk | A grouping of risks by their source, such as legal, financial or technology, from the profile | The kind of work, which is a label |
| Risk appetite | Risk | How much risk of a category an organisation will take to meet its objectives | A tolerance, a limit set for one piece of work |
| Tolerance | Risk | A limit set for one piece of work, such as on cost or time; a breach is flagged and can be escalated | Risk appetite, set for the workspace |
| Escalation | Risk | Passing a risk beyond its owner's authority to a named role that can decide | A handover, which moves accountability for good |
| Dependency | Risk | One piece of work needing another, with an owner and the effect if the other slips | A part-of link, which places one piece of work inside another |
| Profile | Configuration | The data that fits Cartograph to a domain: its taxonomy, results hierarchy, life cycle, deciding roles, required parts, calendar, views and extensions, each chosen from a recognised pattern and mapped to a fixed reference | |
| Taxonomy | Configuration | The terms a workspace uses for levels, labels, stages and roles, each mapped to exactly one standard term in this glossary | Free text a person writes |
| Standard term | Configuration | The term in this glossary that a taxonomy's term maps to, used when the record is exported or shown in a standard's terms | The workspace's own term, shown to its people |
| Results hierarchy | Configuration | The levels a profile arranges results in, chosen from a recognised one (a logical framework, a results framework, objectives and key results), each level mapped to a reference level | A category scheme, such as a balanced scorecard's perspectives, which classifies results without adding a level |
| Reference level | Configuration | One of the four levels every results hierarchy maps to: activity, output, outcome or impact | A profile's own level, which maps to one |
| Reporting period | Configuration | An interval with ISO 8601 start and end dates, generated by the profile's calendar or given explicitly | A cycle, which steers work |
| Extension | Configuration | A method-specific addition, off unless turned on | |
| View | Publishing | A rendering of the record for an audience | A copy |
| Replica | Collaboration | A copy of a workspace's records on one device, usable offline, synchronised encrypted with the others | A backup |
| Draft | Collaboration | A set of changes being prepared, private to its author or shared for live editing, that enters the record only as a proposal | The record, which changes only by accepted proposals |
| Proposal | Collaboration | A set of changes to records, accepted at once or by someone, as the workspace's policy says; an agent's always waits for a person | A review or a decision |
| Journal | History | The append-only list of accepted versions, who, when and why | The index |
| Cryptographic erase | History | Destroying the key that encrypts data, so that every remaining copy becomes unreadable | Deleting a version from the journal, which never happens |
| Restore | History | Making an earlier version current again by appending it as a new version | Deleting later versions, which never happens |
| Language model | Assistance | A model of natural language, such as a large language model ([NIST-GAI](bibliography.md)), behind a port and off by default, asked questions of meaning that rules cannot settle (whether a sentence states one objective or two); it may answer "not judged", and its answers advise, never decide | A decision; an agent, which proposes changes to the record |
