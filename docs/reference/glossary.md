# Glossary

The words of the new model, by context. Inside a context a word means one thing. An organisation may rename any of them in its profile; these are the defaults. For the contexts, see [the domain model](../explanation/domain-model.md).

| Term | Context | Meaning | Not to be confused with |
|---|---|---|---|
| Piece of work | Work definition | The one record of something an organisation does, at any scale | A label such as project or programme, which it carries |
| Label | Work definition | What a piece of work is called (project, programme, portfolio, service, grant, product), from the profile | A separate kind with its own schema, as before |
| Project | Work definition | The label for temporary work that delivers outputs toward an intended result | A programme, whose parts share one change |
| Programme | Work definition | The label for temporary work whose parts together bring about one change and its benefits | A portfolio, whose members need not share an outcome |
| Portfolio | Work definition | The label for an organisation's standing investment in other work toward its goals, with no end; its decisions fund, hold, stop or move money between its members | A programme; a view over many pieces of work, which holds no decisions |
| Case | Work definition | The justification inside a piece of work, organised by five questions: need, value, buying or building, affordability, delivery. Its parts are the change wanted, if nothing is done, intended results, theory of change and assumptions (under need), options (value), cost (affordability) and delivery | A business case document, which is one view of it |
| Intended result | Work definition | A change sought: an output (produced), an outcome (changes for people) or an impact (lasting) | A goal, which is shared strategy |
| Theory of change | Work definition | The steps from what is done to the change, with what must hold at each | The goal tree |
| Assumption | Work definition | Something taken as true that the work rests on, with how much it matters and how well it is evidenced | A risk, which may happen; an assumption may already be false |
| If nothing new is done | Work definition | What is expected if the organisation carries on as it is, with its own costs, benefits and risks | A minimum option, which is one of the options |
| Option | Work definition | A way forward considered, including doing nothing | |
| Decision | Governance | A recorded act by a role with authority (approve, approve with conditions, change the scope, try another option, pilot, defer or stop) on a version of the case | A meaning judgement by the meaning model |
| Condition | Governance | Something a decision requires, with an owner and a due point | |
| Reference life cycle | Governance | The common sequence every life cycle maps to: feasibility, appraisal, definition, delivery and operation, each stage preceded by a decision point | A profile's own life cycle, which maps to it |
| Stage | Governance | A part of the work's life between two decision points, mapped to a reference stage | A cycle |
| Feasibility | Governance | The reference stage that sets out the need and the case for change, and asks whether the work is worth pursuing | Appraisal, which weighs the options |
| Appraisal | Governance | The reference stage that weighs the options' costs, benefits and risks before a decision, and selects one | Evaluation, which looks back at what happened; an economic appraisal model, which Cartograph links to and does not hold |
| Definition | Governance | The reference stage that plans the selected option in full (scope, cost, commercial and delivery arrangements), ending in the decision to invest | The case, which grows through every stage |
| Delivery | Governance | The reference stage, or stages, that produce the outputs | Operation |
| Operation | Governance | The reference stage in which the outputs are used, the benefits realised and the work closed | Handover, one event within it |
| Decision point | Governance | The decision that opens a stage: to go on, change course, hold or stop; also called a gate | A review, which advises it |
| Tranche | Governance | A phase of a programme, grouping projects and related work and ending in a review | A stage of a project |
| Cycle | Governance | A repeating period that work without an end is steered by (a sprint, a quarter, a season) | A stage |
| Review | Governance | An assurance look at the work, recording how independent the reviewer was (self, peer or independent); it advises, never approves | Accepting a proposal |
| Approved plan | Governance | The approved scope, cost, dates and benefits, kept as a named version | The current plan; a baseline |
| Handover | Governance | The acceptance of a result, its benefit tracking and its open risks by the role that carries them on | Closure |
| Indicator | Measurement | What is measured, on what scale, how, by whom, with a baseline and targets | A reading |
| Baseline | Measurement | An indicator's measured starting value, or a stated unknown with when it will be known | The approved plan |
| Reading | Measurement | A value for one period | A target |
| Target | Measurement | What is aimed for, by when; a value, a threshold or a level on the indicator's scale | |
| Aggregation | Measurement | Rolling readings up across pieces of work, periods or groups, by the indicator's aggregation rule | A sum, which is one aggregation rule |
| Disaggregation | Measurement | Breaking readings down by group, such as gender, age or location | A filter, which hides the other groups |
| Benefit | Benefits and learning | An intended result valued by someone, with an owner and an expected date; a disbenefit is a harm, with who bears it | An output |
| Benefit review | Benefits and learning | A judgement after delivery: realised, on track, off track or stopped | |
| Evaluation plan | Benefits and learning | How much checking is proportionate, the decisions it informs and the questions it asks | Monitoring, which is the readings |
| Lesson | Benefits and learning | What was learned, findable by later work | |
| Purpose | Strategy | Why the organisation exists | |
| Goal | Strategy | A result at a level of the profile's hierarchy that work serves | |
| Gap | Strategy | A problem that threatens a goal, and who feels it | |
| Group | Strategy | People or things affected, without counts | |
| Party | Parties and money | An organisation or body with an identity | A person |
| Role | Parties and money | What a party, or a person outside the record, does in the work | |
| Funding line | Parties and money | Money from a source for a period, with currency and status | |
| Risk | Risk | Something that may happen and would affect the work | An issue, which has happened |
| Risk category | Risk | A grouping of risks by their source, such as legal, financial or technology, from the profile | The kind of work, which is a label |
| Risk appetite | Risk | How much risk of a category an organisation will take to meet its objectives | A tolerance, a limit set for one piece of work |
| Profile | Configuration | The data that makes Cartograph speak a domain's language: words, hierarchy, stages, route, required parts, calendar, views, extensions | |
| Extension | Configuration | A method-specific addition, off unless turned on | |
| View | Publishing | A rendering of the record for an audience | A copy |
| Proposal | Collaboration | A set of changes to records, accepted at once or by someone, as the workspace's policy says | A review or a decision |
| Journal | History | The append-only list of accepted versions, who, when and why | The index |
| Meaning model | Assistance | A language model behind a port, asked questions of meaning; it may answer "not judged" | A decision |
